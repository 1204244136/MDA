# MDA 票券生成器

在仓库根目录运行：

```powershell
go -C agent\go-service run ./cmd/ticket-generator -out-dir C:\Tickets
```

生成器支持常规额度重置券、专项额度重置券和活动额度发放券。原 `cmd/quota-refill-generator` 已更名为 `cmd/ticket-generator`。

活动额度发放券需输入时长（整数分钟），可选限定任务入口，例如 `MapPushingFlow`、`EquipmentRerollMain`、`CustomBurstMain`；留空适用于全部计时任务。入口取自 `assets/tasks/*.json` 的 `entry`，须保持大小写一致。还可设置额度有效时长（如 `30d` / `12h` / `90m`，纯数字按天，留空表示永久有效）；该时限从用户实际兑换的时刻起算，与券本身的兑换截止期互相独立。

常规额度按北京时间每日凌晨 4 点刷新，专项额度按会员订阅周期计算；重置券只清零对应额度的已用量，不增加档位额度或延长订阅周期。活动额度发放券按指定时长新增额度。

输入兑换有效天数和可选设备赞助链接后，会生成独立 `.exe` 票券。用户在目标设备运行并按回车兑换，即可向该设备的本地额度记录添加活动额度，无需会员订阅。相同票券在该设备只能兑换一次，不同票券可叠加，且每张券兑换出来的额度互相独立——各自计时、各自过期、各自扣减。赞助链接留空时，每台设备均可兑换一次。

消费顺序为：常规额度 → 专项额度（适用的高级任务）→ 匹配当前任务的活动额度。顺序依据各池的过期紧迫度：常规额度按北京时间每日凌晨 4 点重置，专项额度随订阅周期重置，活动额度按券上设置的期限失效（未设置则永久）——会过期的先用，会员每天的常规额度才不会因为手里攒着活动额度而被整日闲置。同为活动额度时先用限定任务的额度，再用不限任务的额度。倍率由实际扣减的额度池决定：高级任务消耗常规额度时按 5 倍扣减，专项额度与活动额度始终按实际时长扣减。

票券兑换有效期只限制兑换日期；兑换后的活动额度不随每日重置、会员档位或会员周期改变，到期时间只由券上的额度有效时长决定（未设置则永久有效）。原有重置券不会重置或清除活动额度。「额度显示」任务可查看每笔活动额度的剩余时长、任务范围与到期时间，已过期的额度会单独标注。
