# 证据与收敛

本页说明适配为什么以「一帧画面」为起点，以及证据不足时该怎么记录而不是怎么扩大调查。槽位判定与观测阶梯见 [SKILL.md](../SKILL.md)，本页负责伪前提、请求解读、证据记录与停止规则。

## 伪前提

伪前提是文档把某个**具体对象**写成了验证条件，而验证真正需要的是一条**属性**。读的人拿不到那个对象，就会去别处补它。

| 伪前提                               | 实际要求                         | 替代观测                                  |
| ------------------------------------ | -------------------------------- | ----------------------------------------- |
| 必须找到用户裁剪所来自的原始整屏     | 同像素空间、同界面状态的一帧     | `maafw-live screencap --project ./assets` |
| 必须复现裁剪时的那个状态             | 页面当前可复现即等价             | 抓当前帧；状态已消失才用留存关键帧        |
| 必须从画面直接读出 Story、难度编号   | 用已有模板命中反推即可           | Story1 / Normal 模板各跑一次 `reco`       |
| 必须知道裁剪者、裁剪时间、裁剪工具   | 与结论无关                       | 不查                                      |
| 必须先跑 `prepare_templates.py`      | 只有需要缩放/裁切/去背景时才必要 | 1:1 已裁图直接命名归档，回放核实          |
| 必须一次补齐 Normal、Hard 和入口全套 | 只补本次要求的模式               | 只归档本次素材，缺的模式标未知            |

**等价替代**的原则：把要求写成属性（像素空间、界面状态、命中分数），任何满足属性的一帧都可以，来源不参与判定。

## 请求解读

| 用户说                   | 交付物                                      | 不是                   |
| ------------------------ | ------------------------------------------- | ---------------------- |
| 检查工作区内容           | 输入素材清单、当前适配进度、缺口清单        | 溯源报告、文件来历考古 |
| 为某活动适配 Story2 Hard | 模板 + 接线 + 回放分数 + 每张模板的证据状态 | 找原始截图、复现旧页面 |
| 识别不到关卡             | 命中分数、box、模式与列的判定               | 先调低阈值             |
| 补一个既有主题的素材     | 只动该主题与 base，旧 case 保持原样         | 顺手重构共用流程       |

## 证据三态

| 状态       | 判据                                                 | 允许的表述                       |
| ---------- | ---------------------------------------------------- | -------------------------------- |
| 已验证     | 目标模式的帧上命中，记录 `score` 与 `box`            | 「已验证，实机帧 0.95」          |
| 同源未验证 | 与已验证模板同批次、同量级尺寸，但目标状态当前不呈现 | 「同源未验证，左列当前全 CLEAR」 |
| 未知       | 既无命中也无同源依据                                 | 「未知，待补该模式画面」         |

记录位置：template 行尾注释写最简结论与分数；提交正文写帧的来源（分辨率、模式、命中 box/分数）；交付说明写缺口与下一步。只有「已验证」可以写「适配完成」。

## 停止规则

满足任一条即结束本轮调查：

1. 必答项与按主题的槽位都有画面或仓库依据，或已明确标为未知并写明原因。
2. 剩余缺口只能由用户提供（该列已全 CLEAR、该模式未开放、缺少入口 Logo），此时提问或标注，不再扩大范围。
3. 连续两次尝试都没有产生新的可判定观测，把结论降级为未知并汇报。

## 写文档时的自查

写完或审阅任何面向 agent 的文档，逐条问：

- 这句话要求的是**属性**，还是某个**具体文件/对象**？后者改成属性 + 等价替代。
- 有没有「确认 X」却没给**最便宜的观测手段**？补命令、补判据，或说明何时可以标未知。
- 两条路径的详细程度是否暗示了主次？把默认（便宜）路径写在前面，两条路径给同样的完成判据。
- 有没有只写「禁止/不要」却没写正面目标？改成正面行为（观测阶梯、证据三态）。
- 有没有说明**何时可以停**？没有就补停止规则。
- 时间戳、目录名、进程名这类线索有没有被写成调查方向？它们只在能证伪结论时才有价值。
