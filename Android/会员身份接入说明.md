# Android 会员：纯客户端六字段映射

本版本只在 MDA 客户端生成兼容原接口的设备哈希。DoroPay 继续使用原六字段、原权重和原换绑服务，不需要新增协议、数据库列、索引或迁移。

## 映射与原权重

| 原字段     | Android 客户端来源                         | 原权重 |
| ---------- | ------------------------------------------ | ------ |
| cpu_hash   | 特权 Android ID 主哈希                     | 15     |
| uuid_hash  | SN 主哈希                                  | 45     |
| bios_hash  | 从 SN 主哈希按不同字段域派生               | 5      |
| board_hash | 从特权 Android ID 主哈希派生               | 10     |
| disk_hash  | 从特权 Android ID 主哈希派生               | 15     |
| guid_hash  | App Android ID；无效时由本机两个主哈希派生 | 10     |

这些是两三个 Android 来源的兼容编码，不是六个独立硬件特征。SN 对应的权重合计 50，特权 Android ID 合计 40，App Android ID 或其兜底项为 10。匹配门槛保持原来的 80：App ID 出现、消失或变化只影响 10 分，仍至少得 90 分；SN 或特权 Android ID 变化不足以通过门槛，需要使用换绑服务。

SN 和特权 Android ID 均必须有效；缺失任意主来源时返回空设备码并提示采集未就绪，不用全零、UNKNOWN、空串哈希等共同占位值填充。App ID 为空、全零或未通过校验时，GUID 用本机已有的两个主哈希派生，因此仍是该设备自己的值，不是所有手机共用的固定值。

SN 固定优先级为 `ro.boot.serialno`、`ro.serialno`、`Build.getSerial`、policy API。IMEI、MEID、MAC、Wi-Fi 状态和 sysfs 不参与会员映射，采集代码中也不包含这些读取逻辑。

## 哈希约定

哈希输入为 UTF-8：`mda:android:client-v1:<field>:<source>` + 一个 NUL 字节 + 值。各字段与来源使用不同前缀，避免和桌面直接对硬件值求哈希的结果混淆。

- UUID：field=`uuid`，source=`serial`，值为归一 SN。
- BIOS：field=`bios`，source=`serial-root`，值为 UUID 主哈希。
- CPU：field=`cpu`，source=`android-id-privileged`，值为归一特权 Android ID。
- Board / Disk：field=`board` / `disk`，source=`privileged-root`，值为 CPU 主哈希。
- GUID：App ID 有效时 source=`android-id-app`；无效时 source=`primary-fallback`，值为 UUID 哈希 + NUL + CPU 哈希。

Android ID 作为最多 64 位十六进制数归一为 16 位，排除全零及已知占位值；SN 排除空值、已知默认字符串和脱敏值。所有输出均为小写 64 位 SHA-256。

## 兼容边界

HTTP 请求和赞助 URL 仍只有原六字段，不发送 device_schema 等新协议参数。Windows 设备生成逻辑、MatchDeviceCodeV7 权重、DoroPay API 校验和数据库结构均不变。

手机与电脑的源哈希使用不同编码域，但这不是服务端的平台权限隔离。电脑和手机必须分别使用不同的用户 ID、分别开通；原 DoroPay 仍可能允许同一个 ID 被重新绑定，所以提示文案明确说明不要混用 ID，换绑前确认目标设备。

客户端通过派生字段之间的关系识别本映射，用两个主哈希计算本地额度身份。App ID 或兜底项切换不会重置每日额度、活动券；从赞助 URL 解析设备时同样可以识别，无需额外平台参数。会员离线缓存、定向额度券仍使用原六字段和原权重匹配。

系统重置、切换用户或 root/shell 可能改变主来源；此时按原换绑服务处理，不承诺所有情况下自动延续。

## 构建与验证

会员联调包由 [Android CI](CI测试包说明.md) 生成，统一使用 major ≥ 1 的非 dev 版本，包名 `com.aliothmoon.maafw.mda.membershiptest`，启用实际会员与额度检查。PR 验证包和开发包使用独立包名。

本地校验包括 Go 映射/原权重/额度回归，以及 `node --test tools/verify/test_android_membership_contract.mjs`：使用旁边 DoroPay 原版 Worker 和原版 schema，在独立 Miniflare D1 验证映射注册、订阅、查询、App ID 变化和换绑。不调用线上服务，不需要新服务端部署。

真机验收需要确认会员/额度检查、链接六字段完整性、覆盖更新、重启后的识别及换绑流程。实际开通前核对目标用户 ID；离线测试通过不等同于已完成正式会员真机验收。
