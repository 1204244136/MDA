## 详细规则

### 1. 锁定材料改在实际刷取时扣除

公告说明，旧机制存在“锁定顺序不同，导致自订密钥消耗不同”的问题。调整后的操作阶段为：

1. 锁定效果：选择锁定材料。
2. 变更效果或重置数值：消耗材料。

这里明确改变的是扣除时点。图片没有给出锁定数量与材料消耗的对应关系，也没有说明取消锁定、切换材料或放弃操作时的详细处理方式，不能据此写出新的完整成本公式。

### 2. 可读取并套用先前的单次锁定信息

适用对象是“先前用自订密钥设定的单次锁定资讯”，目的为提升自订密钥重复使用的便利性。

“可读取并套用”不等于每次自动沿用。截图未说明是否跨装备、跨妮姬、跨界面或跨登录保存，也未说明锁定信息具体包含哪些字段。

### 3. 同栏位出现重复效果或数值时可重抽

公告同时提到两种操作：变更效果、重置数值。其判定描述包含两个限定：

- 比较位置是同一个栏位。
- 比较对象是前次的效果或数值。

满足重复条件时，公告表述为“可重新抽取数值”。另外明确例外：“未获得效果”仍可能重复出现。

因此，不能将这项调整理解为必定获得三条效果、所有栏位之间均不可重复，或最终结果必定优于原结果。公告没有明确重抽的交互方式、额外成本、次数上限，以及效果变更与数值重置各自的完整判重算法。

### 4. 可查看当前改造装备的追加效果总和

- 入口：妮姬详细资讯画面的装备栏新增图示。
- 显示条件：该妮姬至少装备 1 件改造装备。
- 展示内容：当前装备的改造装备所提供的追加效果总和。

这里汇总的是当前所穿改造装备的追加效果，不是仓库内所有装备，也未宣称涵盖角色全部属性来源。图示的具体外观未可靠转写。

### 5. 丧失 15 阶段效果前增加继续确认

在变更效果或重置数值时，如果会导致丧失 15 阶段的效果，游戏会询问是否继续操作。

截图未展示弹窗文案、按钮布局和触发时点的更细粒度顺序，也未说明“一条或多条 15 阶段效果”“效果消失或数值下降”等情形如何分别判定。

### 6. 指挥官低于 100 级也可刷取

效果变更与数值重置不再因指挥官等级低于 100 级而不可用。图片没有说明改造装备的获取条件、其他前置条件或材料要求同时发生变化。

### 对现有实现的初步影响

- `plan.go` 中的 `countQuotaEffects`、`AllPartsSatisfiedQuota` 使用效果条数和禁止效果进行角色目标判断。官方面板若能完整识别所有效果及蓝色部位图标，可支持更早判断已达标，减少为此目的进行的逐件扫描。
- `monitor.go` 的 `partScan`、`inspect.go` 的前置扫描还记录槽位与锁状态；`DesiredLockSlotForQuota` 等决策需要这些信息。本页没有显示具体第 1/2/3 槽、各槽数值、档位、永久锁或单次锁，不能直接替代完整快照。
- 总百分比不能当作词条条数；部位图标的颜色含义及顺序需要通过单件详情核对。
- 本张图只有四种效果，尚不能确认更多效果时是否滚动、扩展面板，或改变卡片位置。未显示的效果暂不能一律视为不存在。
- 决定先补充观察，再修改运行代码；这不是代码修改已完成的记录。

下一步优先观察：效果种类超过四种的角色面板（含列表底部，如可滚动）；当前角色一件装备的详情（例如身躯，用来交叉核对蓝／灰部位标记及槽位信息）。

不需要继续收集四种或五种效果的重复样本。当前样本已经确认：

- 总览可按效果名称读取总值与部位分布；
- 效果卡片位置会变化，不能按固定格子解释；

## 架构决策与收敛优化（2026-09-20）

在实机探索完成后，遵循“Pipeline 负责基础识别、Go 负责复杂业务”的设计原则，进行了系统性收敛与优化：

1. **拆除总览预检脚手架**：
    - “查看装备效果”总览在实机探索中验证了卡片分布与部位图标语义，但其布局高度动态且缺少具体槽位与锁状态，最终仍需完整扫描；
    - 为避免在 Go 中循环动态注入 50+ 次识别带来的过度工程化与潜在脆弱性，总览预检仅作为前期脚手架，正式落地时彻底拆除，保持四件装备扫描的统一稳健路径。
2. **纯粹声明式 Pipeline 编排**：
    - 移除中间冗余的 `CustomRecognition`，让 Pipeline 节点（如 `EquipmentRerollReloadLocks` 亮蓝按钮）直接进行声明式匹配与点击，Go 仅负责纯粹的状态转移与快照同步；
    - 费用准备由 Action 直接在确认页校验并暂存，结果页原子记账，彻底杜绝重复扣费与数据冗余。
3. **精简测试架构**：
    - 清理所有依赖外部图片的测试脚手架与 16 张临时截图，全量回归收敛为纯 Go 业务与算法单元测试，秒级运行零环境依赖。

## 确认页库存兜底同步：流程脱节修复（2026-09-20）

实机日志包 `MDA-logs-0.1.0-20260920-210830-part001.zip`（task_id 200000001）暴露了一处流程脱节：任务 13 秒即「成功」结束，一次效果变更都没执行。

### 现象与证据

- 节点轨迹中**没有** `EquipmentRerollLockPageEntered` / `EquipmentRerollMaterialCheck`。本轮臂部三槽词条均不在配额内（实机配额为优越代码 4 / 攻击力 4 / 最大装弹 4），锁定判定正确得出「无需锁定」，流程由 `EquipmentRerollClickChangeEffect` 直接进入确认页。
- 库存初始化的唯一入口正是「进入效果锁定页」，因此从未执行；`go-service.log` 中既无 `material inventory initialized`，也无 `material OCR incomplete`。
- 确认页费用校验读到的是 `getInventory` 的零值，日志记为 `insufficient materials for effect change`（`inventory: {custom_modules:0, custom_lock_keys:0}`），随即 `routeEquipmentRerollEnd` 结束任务。

- `lock.go` 的 `no affordable lock material` 是误导性文案：`desiredLockPlanForInventory` 返回 false 的两种原因（材料不足 / 策略不需要锁）被合并成同一条告警，会把排查方向带偏。

### 修复内容

1. **确认页兜底同步库存**：新增 Pipeline 节点 `__EquipmentRerollHeldLabel`（定位「持有材料」文字）与 `__EquipmentRerollConfirmHeldModule`（相对定位其右侧数量，`roi_offset: [45,-10,105,34]`），以及 Go 识别器 `EquipmentRerollSyncInventoryRecognition`。节点 `EquipmentRerollSyncInventory` 挂在确认页哨兵 `EquipmentRerollKeepLockGate` 的 next 首位；识别到持有量才命中，否则落到哨兵的后续节点。页面归属由挂载点与「持有材料」锚点共同保证，Go 不重复判定页面。确认页后续链（载入历史锁 → 锁定判定 → 读取本轮费用）抽到 `EquipmentRerollConfirmPageBranch` 一处维护，哨兵与同步节点都指向它，避免链在多处重复书写。
2. **按材料独立跟踪持有量**：`monitorState` 新增 `ModulesHeldKnown` / `KeysHeldKnown`。确认页在无密钥费用时不显示密钥持有量，因此只写模块；`getModulesHeld` / `getKeysHeld` 供费用校验使用，`getInventory` 保持「两种材料齐全」的锁定决策语义。
3. **费用校验区分「未读到」与「读到且不足」**：新增 `guardRerollCost`，只有明确读到余额不足才结束任务；未读到库存时放行并把费用照常暂存，由游戏侧材料校验兜底。
4. **结束路径输出摘要**：`routeEquipmentRerollEnd` 改为跳转 `EquipmentRerollFinalSummary`，材料不足 / 配额不可达等提前结束不再表现为「静默成功」。
5. **修正锁定规划日志**：`desiredLockPlanForInventory` 改为返回 `lockPlanOutcome`（需要锁 / 不需要锁 / 付不起 / 未知），四种结论分别记录。
