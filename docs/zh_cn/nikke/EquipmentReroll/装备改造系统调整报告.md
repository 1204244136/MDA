## 详细规则

### 1. 锁定材料改在实际刷取时扣除

公告说明，旧机制存在“锁定顺序不同，导致自订密钥消耗不同”的问题。调整后的操作阶段为：

1. 锁定效果：选择锁定材料。
2. 变更效果或重置数值：消耗材料。

这里明确改变的是扣除时点。图片没有给出锁定数量与材料消耗的对应关系，也没有说明取消锁定、切换材料或放弃操作时的详细处理方式，不能据此写出新的完整成本公式。

### 2. 可读取并套用先前的单次锁定信息

适用对象是“先前用自订密钥设定的单次锁定资讯”，目的为提升自订密钥重复使用的便利性。

“可读取并套用”不等于每次自动沿用。截图未说明是否跨装备、跨妮姬、跨界面或跨登录保存，也未说明锁定信息具体包含哪些字段。

### 3. 同栏位出现重复效果或数值时可重抽

公告同时提到两种操作：变更效果、重置数值。其判定描述包含两个限定：

- 比较位置是同一个栏位。
- 比较对象是前次的效果或数值。

满足重复条件时，公告表述为“可重新抽取数值”。另外明确例外：“未获得效果”仍可能重复出现。

因此，不能将这项调整理解为必定获得三条效果、所有栏位之间均不可重复，或最终结果必定优于原结果。公告没有明确重抽的交互方式、额外成本、次数上限，以及效果变更与数值重置各自的完整判重算法。

### 4. 可查看当前改造装备的追加效果总和

- 入口：妮姬详细资讯画面的装备栏新增图示。
- 显示条件：该妮姬至少装备 1 件改造装备。
- 展示内容：当前装备的改造装备所提供的追加效果总和。

这里汇总的是当前所穿改造装备的追加效果，不是仓库内所有装备，也未宣称涵盖角色全部属性来源。图示的具体外观未可靠转写。

### 5. 丧失 15 阶段效果前增加继续确认

在变更效果或重置数值时，如果会导致丧失 15 阶段的效果，游戏会询问是否继续操作。

截图未展示弹窗文案、按钮布局和触发时点的更细粒度顺序，也未说明“一条或多条 15 阶段效果”“效果消失或数值下降”等情形如何分别判定。

### 6. 指挥官低于 100 级也可刷取

效果变更与数值重置不再因指挥官等级低于 100 级而不可用。图片没有说明改造装备的获取条件、其他前置条件或材料要求同时发生变化。

## 界面观察与适配结论

以下是已有样本支持的观察，区别于上文公告原文。个人角色、装备快照、持有量、截图文件标识及故障时间线不在公开文档中保留。

### 装备效果总览

- 已观察到四、五、七种效果的布局：卡片按两列排列，弹窗会随行数增高，效果卡片位置会变化，应按效果名称或锚点定位。
- 图标外观从左至右对应头部、身躯、臂部、腿部，与代码中的部位数组顺序不同，不能直接按索引套用。
- 总览中的蓝色部位标记与单件详情进行过交叉核对，可用于建立效果与部位的对应关系；颜色不是锁状态。
- 总览缺少槽位顺序、各槽数值与锁信息，不能替代完整详情快照。八、九种效果的布局及滚动行为仍缺少验证。

### 锁定与费用

选择密钥后 SELECT 文字仍存在，应通过选中态或可用的确认按钮区分阶段，不能因文字未消失而重复点击。确认锁定后返回重洗确认页；库存统计不应在选择或确认锁时扣减。

以下是已观察的费用组合，数值是规则样例而非个人库存。费用识别仍须读取当前页面总额，不能用样例替代运行时校验。

| 状态                                 | 确认页总费用              |
| ------------------------------------ | ------------------------- |
| 无锁                                 | 1 模组                    |
| 新增一把单次锁                       | 2 模组 + 20 密钥          |
| 新增两把固定锁                       | 8 模组（3 基础 + 5 锁费） |
| 先新增一把固定锁，再新增一把单次锁   | 5 模组 + 20 密钥          |
| 保留一把既有固定锁                   | 2 模组                    |
| 保留一把既有固定锁，再恢复一把单次锁 | 3 模组 + 30 密钥          |

既有固定锁跨轮保留，不重复收取已经支付的固定锁费用。历史加载按钮可在存在固定锁时使用，但必须比较完整计划并核验加载结果，不能仅凭按钮可用就执行。

### 识别与结果提交

- 锁图标会明暗变化，有限采样不能证明某个颜色阈值对所有相位、页面与设备有效。未知帧应继续等待，空槽则需明确的“未获得效果”证据。
- 单次锁解除提示可能遮挡结果文字。有可信的本轮锁定快照时，可沿用受保护槽的效果和数值；不能用跨轮历史锁位猜测。
- “丧失最高阶段效果”是流程确认，维持与接受分支应分别返回对应路径，不能让维持动作提交接受候选。
- 库存 OCR 应区分标签与数字、归一化千位分隔符，并分别记录“未知”和“已知但不足”。
- 页面识别、相对坐标和颜色参数由 Pipeline 维护；Go 负责快照、计划准入、费用解释和原子提交。

本节保留可复用观察，不承诺覆盖全部组合或代表端到端验收。当前任务结构见[任务说明](README.md)，数值分支的验证范围统一见[验证边界](洗词条数值实现.md#验证边界)。本地截图不是仓库附带的测试夹具。
